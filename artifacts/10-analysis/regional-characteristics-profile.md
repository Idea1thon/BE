# 지역 특성 프로파일 명세

- 작성: 2026-09-01 (사용자 틀 기반)
- 상위 계약: `.claude/context/metric-contract.md`(근거 차원), `.claude/context/data-catalog-contract.md`(데이터 상태)
- 데이터 근거: `artifacts/10-analysis/data-integrity-check.md`, `data-inventory.md`
- 소비처: `artifacts/20-method/candidate-selection-spec.md`(3절 근거 차원), `artifacts/20-method/rag-evidence-schema.json`

## 1. 목적과 경계

- **지역 특성 = 업종·특별조건과 무관하게** 상권/행정동이 "어떤 곳인가"를 서술하는 중립 프로파일이다.
- 좋은 입지 판정(추천/조건부/주의)은 하지 않는다. 판정은 `candidate-selection-spec.md`가 이 프로파일 + 사용자 업종·조건으로 수행한다.
- 예: 프로파일 = "직장인구 상위 12%, 유동 최근 1년 −6%, 커피 점포밀도 상위 8%, 진입환경 '주의', HH(고착)". 판정 = "커피·배달중심·예산300 → 조건부 검토".

## 2. 산출 단위와 시점

- **프로파일 대상은 지점**(아파트 단지·역, `candidate-selection-spec.md` §1). 지점별로 아래 grain을 조합한다:
  - **지점 반경 250~500m 직접 계산**(원천 좌표 보유): FC-07 역·버스, FC-08 아파트. → 지점 고유값, `grain_is_proxy=false`.
  - **포함 상권 → 없으면 행정동 배경값**: FC-01·02·03·04·05·10·11·12·30·31·32·40·50. → `grain_is_proxy=true`(지점이 상권/행정동 centroid 아님), `proxy_note`에 "포함 상권 배경값" 또는 "행정동 배경값" + host 상권 거리. (FC-10은 전 업종 통합 상권/행정동 진입 환경.)
  - **자치구/권역/서울시**: FC-20·21·41·42·52·53. → 기존대로.
- 업종 지표(FC-30·31·32·12): 포함 상권에 대상 업종 행이 있으면 상권×업종, 없으면 행정동×업종(`점포-행정동`·`추정매출-행정동`). 둘 다 없으면 null + `greenfield`.
- (구) 상권/배후지 단위 후보는 seed(아파트·역)가 없을 때만 fallback. 그때는 상권 centroid 기준 `grain_is_proxy=false`.
- `as_of_quarter`: build마다 데이터별 실제 관측 종료 분기 재계산(spec 0-8). 2026-09-01 기준 분기 시계열(유동·매출·점포·변화지표) = 20261, 임대료 = 2025Q4.
- 계단식(상주·직장인구)의 `as_of_quarter`는 분기 코드가 아니라 **각 지역 값이 마지막으로 실제 변한 분기**로 기록한다. 이 분기 산출은 아직 미검증(값 수준 검사 필요) — 확정 전까지 `as_of_quarter.resident/worker`에 `"미검증"`을 넣고 신뢰도를 낮춘다. 본문 예시 JSON의 분기값은 형식 예시일 뿐 실측이 아니다.
- feature table는 `candidate-selection-spec.md` 0절 결합 규칙을 통과한 정규화 테이블만 사용. 원천 CSV 직접 조인 금지.

## 3. 상태 코드

| status | 의미 |
| --- | --- |
| `active` | 현재 데이터로 계산 가능 |
| `partial` | 계산은 되나 grain 또는 갱신 주기 제약이 큼(권역 grain, 계단식) |
| `inactive` | 필요한 데이터가 저장소에 없음. 프로파일에는 슬롯으로 존재하고 값은 `null` |

`inactive` feature도 프로파일 객체에 **항상 포함**한다(4·6절). 데이터가 확보되면 슬롯 규격(6절)에 맞춰 채우고 `status`만 바꾼다 — 스키마·소비처 코드 변경 없이 이식된다.

## 6. 이식(플러그인) 규약

없는 데이터가 나중에 확보되면 아래 절차로 재설계 없이 붙인다.

1. **슬롯은 항상 존재**: `inactive` feature도 프로파일 JSON·RAG evidence·신뢰도 계산에 포함된다. `value=null`, `missing_reason`, `activation` 블록 유지.
2. **활성화 절차**:
   a. 새 데이터를 `auditing-location-data` 스킬로 감사 → `data-catalog-contract.md`의 해당 `missing` 행을 `core`/`conditional`로 승격, grain·기간·키·커버리지 기록.
   b. 해당 feature의 `activation.formula_when_active`를 계산식으로 확정, `status` → `active`/`partial`.
   c. 지역 특성 프로파일 재빌드.
   d. 의존 산출물(`candidate-selection-spec.md`, `rag-evidence-schema.json`, 최종 명세) `stale` 표시 → 부분 재실행.
3. **슬롯 규격**(각 inactive feature가 반드시 갖는 필드):

```json
"activation": {
  "needs_dataset": "외국인 생활·방문인구",
  "min_fields": ["공간코드/좌표", "국적/체류유형", "인구", "기간", "기준일"],
  "grain": "상권 또는 point-in-polygon",
  "min_freshness": "최근 4분기 중 1개 이상",
  "formula_when_active": "외국인 방문인구 / 전체 방문인구, 최근 4분기 평균",
  "catalog_row": "data-catalog-contract.md > 외국인 방문 (missing)",
  "downstream_dimension": "수요 구성"
}
```

4. **소비처 계약 고정**: `candidate-selection-spec.md`·RAG는 feature를 **id로 참조**하고 `status`를 읽는다. `inactive`면 자동으로 `missing_features`에 넣고 등급 상한을 낮춘다. 데이터가 붙어도 참조 코드는 그대로.

## 7. `entry_health_v1` 산식 (충돌① 조건부 허용 — 확정 2026-09-02)

공실률·점포·4대분류를 **하나의 서수 등급**으로 묶되, ADR-001을 지키기 위한 조건을 모두 만족한다. 설계 근거·검증: `artifacts/20-method/entry-health-v1-cut-design.md`, `output/entry_health/`.

- **정체성**: **지역(상권/행정동) 배경 진입 환경 등급 — 업종 구분 없음**. 점포 성분을 전 업종 통합해 계산한다. 이유: `상권_변화_지표` 라벨이 전 업종 통합 산출값이라 grain 일치가 필요하고, 업종별(예: 커피) 개·폐업률은 상권×업종 grain에서 71%가 0이라 분위가 무의미. 업종별 진입 신호는 FC-11·FC-12·FC-30이 담당.
- **출력**: `grade ∈ {양호, 보통, 주의, 경계}` (+ 지점이 상권·행정동 밖이면 `정보없음`) + 입력 분위 4개·산식·컷 전부 노출. 연속 `risk`는 내부용, `score_is_predictive=false`.
- **변형**: `core`(아래 4성분) = 기본. `enriched`(+공실률 권역 분위) = 정의만, R-ONE 공실률 CSV 이식·`join_eligible` crosswalk 연결 전이라 비활성.
- **입력**: 전 업종 통합 상권(또는 행정동)의 폐업률·개업률·점포_증감률 → 각각 서울 분위(0~100). 라벨 → 리스크 점수.

| 라벨 | 해석 | 리스크 |
| --- | --- | --- |
| LH 상권확장 | 신규 업체가 경쟁력 | 낮음 (0.0) |
| HH 정체 | 신규·기존 모두 진입장벽 높음 | 중간 (0.5) |
| LL 다이나믹 | 신규개발, 검증된 장기생존 없음 | 중간-주의 (0.6) |
| HL 상권축소 | 기존 우위, 신규 불리 | 높음 (1.0) |

- **결합 산식**: `risk = 0.25·폐업률분위 + 0.25·(100−개업률분위) + 0.25·(100−점포증감률분위) + 0.25·(라벨리스크·100)`
  - 성분 결측 시 존재 성분만 동일가중 재정규화. 라벨 결측 시 리스크 0.5(실측 0건).
  - 잠정안(`0.30·폐업 + 0.20·순개업 + 0.20·증감 + 0.30·라벨`) 대비: 순개업률(개업−폐업)→개업률 단독(폐업 이중계상 제거), 동일가중.
- **등급 컷 (20261 서울 사분위 동결, scope별)**: 상권 `risk<41 / <51 / <62 / ≥62`, 행정동 `risk<42 / <52 / <61 / ≥61`. 분기마다 재계산하지 않음. 라벨과 단조 정렬 확인(HL 셀 56%→경계, LH→양호).
- **판정에서의 사용**: 등급은 **반대근거 1항목**으로만(주의·경계일 때). `fit_tier` 게이트·정렬키로 승격 금지.
- **버전 관리**: 가중치·라벨 매핑·컷 재동결 변경 시 `entry_health_v2`로 올리고 프로파일에 버전 기록.
