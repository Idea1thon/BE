## 0. 한 줄 요약

**데이터 하네스는 "가중 합산 입지 점수"를 만들지 않는다.** 서울 상권 데이터로 몇 주간
검증한 결과, 폐업/생존을 예측하는 결합 가능한 연속 신호가 없었다(§3-D1). 하네스는
대신 **하드 조건 + 근거 차원 + 3분류 판정(추천 / 조건부 검토 / 주의)** 을 낸다.

명세 REQ-LOC-01("현재 수요 점수 + 미래 가치 점수의 가중 합산")과 이 접근이 정면으로
다르다. 입지 추천을 서비스로 만들려면 **미결 #1(입지 점수 가중치)을 "가중합산 폐기,
근거 판정으로 재정의"로 합의**하는 것이 선행 과제다.

## 1. 하네스가 하는 일 (입지 추천 관점)

정본 구현: [`scripts/recommendation_pipeline.py`](../scripts/recommendation_pipeline.py). CLI 실행 → `output/recommendation_runs/<slug>/`.

```
입력(시도·시군구·동·업종·특별조건)
  → 지역 폴리곤 확정 + 300m 버퍼
  → 지점 seed 생성 (검증된 아파트단지·역 + 선택: 카카오POI·격자 합성좌표)
  → 지점마다:
       공간 결합 (지점 PIP → 포함 상권 / 같은 자치구 최근접 ≤300m / 행정동 배경값)
       피처 추출 (업종 점포·추정매출·유동·변화지표·역·버스·아파트·entry_health·임대료·검색관심도·뉴스)
       근거 3버킷 분류 → fit_tier 판정
  → 정렬 (tier → 후보타입 라운드로빈 → 반대근거 수 → 신뢰도 → id)
  → RAG 스키마 검증 → 산출물(candidates.json, coverage-summary.json, run-manifest.json, run-notes.md)
```

**출력 = 후보 카드.** 각 카드: 지점 위치(시>구>동>앵커명 "인근">좌표) · fit_tier · 강점 근거(reasons) ·
반대 근거(counter_evidence) · 배경 서술(context_notes) · 지표별 evidence(출처·grain·해석·한계) ·
누락 데이터(missing_features) · 데이터 신뢰도. `fit_index=null`, `score_is_predictive=false`.

### 근거 3버킷 (판정에 어떻게 쓰이나)

| 버킷 | 무엇이 들어가나 | fit_tier·정렬 영향 |
| --- | --- | --- |
| `reasons` (강점 키워드) | **약한 배경 신호만** — 배후 아파트 3,000세대+, 업종 매출 서울 상위 30%+, 버스 8개+ | 판정 입력. **2개 이상**일 때만 추천 가능 |
| `counter_evidence` (주의 키워드) | 진입 리스크 등급(FC-10)·상권변화 라벨 HH/HL(FC-11) + 하드조건 미충족 + 매출 미제공 + 임대료 proxy | 판정 입력. 정렬 2순위 |
| `context_notes` (배경 서술) | 유동밀도·점포밀도·역거리·프랜차이즈비율·검색관심도·뉴스 보도량 등 **검증에서 신호 없던 지표** | **미반영** (카드에 참고 서술로만) |

판정 규칙:
```
blocking(counter에 "불리"/"리스크 경계") AND len(counter)>=3  → 주의
하드조건 미충족 OR 매출근거 없음 OR reasons<2개               → 조건부 검토
그 외                                                        → 추천
합성 격자 좌표는 '추천' 상한을 '조건부 검토'로 캡
```

## 3. 확정된 설계 결정 (근거 포함) — 팀이 바꾸려면 이 근거를 반박해야 함

### D1. 가중 합산 입지 점수를 만들지 않는다 (evidence-first)

- **근거**: [`artifacts/10-analysis/feature-evidential-value.md`](../artifacts/10-analysis/feature-evidential-value.md) — 서울 전체 상권×업종으로 각 지표 ↔ 인허가 폐업/생존 실측. **연속 지표 27개 중 폐업/생존에 단조 신호(|Spearman ρ|≥0.25)를 가진 것 0개.** 전체 지표를 합쳐도 설명력 +6%p.
- Phase 1 실험: 전체 피처 가중 모델 F1 0.93 = **과거 매출을 재현한 동어반복** ([`docs/스코어링_추천모델_보고서.md`](스코어링_추천모델_보고서.md)).
- [`artifacts/adr/ADR-001-evidence-first-ranking.md`](../artifacts/adr/ADR-001-evidence-first-ranking.md) — 불투명 학습 순위를 운영 근거로 쓰지 않음.
- **그래서**: 점수 자리에 tier 배지(추천/조건부 검토/주의) + 근거 요약. `fit_index`를 만들더라도 `score_is_predictive=false`, 공개 산식의 표시 정렬 휴리스틱까지만.

### D2. 후보 = 지점, 상권/행정동 폴리곤이 아니다

- **근거**: 상권 폴리곤은 서울 면적의 27%만 덮고 크기 편차 20배. 결함 케이스 F21(상권 폴리곤을 후보로 내보냄 → 반려).
- **그래서**: 후보는 좌표를 가진 지점(아파트단지·역·카카오POI·격자 합성좌표). 지점이 참조하는 상권/행정동은 **배경값**(`grain_is_proxy=true`)으로만 표기. 명세의 "행정동 카드"는 탐색·그룹 레벨로 해석.

### D3. 매출 미제공(상권×업종 54%)을 넓은 grain으로 fallback하지 않는다

- **근거**: [`artifacts/10-analysis/value-level-qa.md`](../artifacts/10-analysis/value-level-qa.md) — 추정매출은 카드거래 표본이 임계치 미만인 상권×업종을 **의도적으로 추정 안 함**. "데이터 없음"이 아니라 "이 상권에서 이 업종 시장이 작을 수 있음"이라는 신호. 배후지·행정동 매출로 채우면 과대평가.
- **그래서**: 매출 미제공 상권은 `조건부 검토` 유지 + "추정매출 미제공 — 카드거래 표본 임계치 미만" 사유 기록.
- 참고: `당월_매출_금액`은 **분기 합계**(단위 `원/점포·분기`). 컬럼명이 "당월"이라 오해 주의.

### D4. 뉴스·검색관심도·POI·유동밀도·점포밀도 = context_notes 전용

- **근거**: FC 신호 등급표([`regional-characteristics-profile.md`](../artifacts/10-analysis/regional-characteristics-profile.md) §9-1). 위 지표들은 검증에서 폐업/생존과 무연관이거나(FC-01·30·40·41) 업종 전체 상수라 미신뢰(FC-42) 또는 지역 무관.
- **그래서**: 카드에 참고 서술로 표시하되 fit_tier·정렬·data_confidence에 반영 안 함. 뉴스/POI on·off 비교에서 후보 ID·순서·등급 불변을 회귀 테스트로 검사.
- 실무 함의: 명세 REQ-LOC-02·03이 점수 축으로 삼은 대부분이 여기 해당. **점수 요소가 아니라 "보여주는 맥락".**

### D5. 계단식 데이터(상주·직장·아파트인구)의 증가율·추세는 만들지 않는다

- **근거**: memory·전수 점검 — 이 데이터들은 분기마다 안 바뀌고 계단식으로 갱신됨. 분기 트렌드 피처는 아티팩트.
- **그래서**: 수준(비율·분위)만 사용. 명세 REQ-LOC-03의 "상주인구 **증가 여부**"는 측정 불가.

### D6. 상주·직장인구 수준을 존속 가능성 근거로 승격하지 않는다 (2026-09-03 검증)

- **가설**(사용자): 상권 유형(신도시형 미성숙 / 골목형 성숙)으로 나누면 상주·직장인구가 존속 신호가 될 것.
- **검증**: [`artifacts/10-analysis/site-typology.md`](../artifacts/10-analysis/site-typology.md) 1·2단계. 상권 유형 분류기 구축 후 유형별 층화로 인구 수준 ↔ 폐업/생존 상관 실측.
- **결과**: 유형 무관하게 |ρ|<0.2. 유형 자체의 baseline 차이도 대부분 자치구 구성 효과. **가설 미지지.**
- **그래서**: 상주·직장인구는 "현재 수요·수요 구성" 차원의 **배경 서술**로만("배후 직장인구 N명, 서울 상위 X%"). 존속 근거·점수 요소 아님. 파이프라인 미연결 유지.
- 남은 가능성(검증 불가): "이 입지가 20년 뒤에도 상권으로 유지되는가"는 상권 소멸 시계열(관측기간 부족)·신규 점포 매출 outcome(없음)이 있어야 답할 수 있음.

## 4. 알려진 한계 — 팀이 반드시 알아야 할 것

### 4-1. 정확한 매물 주소·링크·월세·면적·층·주차 = **없다** (미해결 갭)

- 개별 상가 매물 데이터가 저장소에 없고, 개별 상가 크롤링은 불법이며 확장성이 없다.
- 대안으로 **격자 합성 좌표**를 만들었다([`artifacts/10-analysis/generated-gridpoint-seed-audit.md`](../artifacts/10-analysis/generated-gridpoint-seed-audit.md)): 100m 격자 → 영업 중 음식점 인허가 반경 집계로 필터한 좌표. `synthetic_anchor=true`, `precision=지점(생성)`, `listing_url=null`, `address_point=null`, 카드에 "프로젝트가 생성한 좌표" 고지, fit_tier 상한 `조건부 검토`.
- **이건 매물 데이터의 대체가 아니라 그 공백을 명시적으로 드러내는 장치다.** REQ-HQ-20·LOC-08의 "정확한 매물 주소"는 여전히 채워지지 않는다. → **미결 #7(부동산 매물 API)** 확보 전까지 카드는 "행정동 + 근처 앵커(역·아파트) + 반경 경쟁 규모"까지만 낸다.

### 4-2. 상권×업종 추정매출 커버리지 54%

- 나머지 46%는 fallback 없이 "매출 검증 불가"로 표기(§3-D3). 매출을 핵심 근거로 기대하면 절반의 후보에서 빠진다.

### 4-3. 신규 점포 성공·매출·손익 outcome이 전혀 없다

- 하네스가 검증에 쓴 outcome은 전부 **인허가 폐업/생존·점포 교체 프록시**. "이 자리에 새 가게를 내면 성공하는가"는 이 데이터로 검증 불가.
- 그래서 모든 근거에 "과거 실적이며 신규 성공 아님" 주석이 붙는다.

### 4-4. 미래가치 = 검증된 신호 1개(유동추세)뿐

- FC-02(최근 4분기 유동 선형 기울기)만 "미래 신호"로 검증됨. 나머지(상주·직장인구, 재개발, 고용, 뉴스, 검색)는 서술 또는 미검증.
- 재개발(FC-51)은 사업 데이터로 "현재 추진단계"만 서술. 발표일 시계열이 없어 "착공 예정 2027" 같은 표현 금지.

## 6. 입지 추천 파트 — 팀이 만들 것 (권장)

1. **하네스 파이프라인을 API 뒤에 둔다.** 입력 DTO는 [`input-and-condition-contract.md`](../artifacts/10-analysis/input-and-condition-contract.md), 응답 DTO는 [`candidate-selection-spec.md`](../artifacts/20-method/candidate-selection-spec.md) §7 + [`rag-evidence-schema.json`](../artifacts/20-method/rag-evidence-schema.json). 상세 아키텍처는 [`docs/architecture/recommendation-web-service.md`](architecture/recommendation-web-service.md).
2. **카드 UI**: fit_tier 배지 + `reasons`(강점 ≤3) + `counter_evidence`(주의 ≤2) + `context_notes`(펼침 배경 서술) + `missing_features`(누락 데이터) + `data_confidence`.
3. **점수를 표시하려면**: 근거 차원별 상태(현재수요·경쟁·진입건전성·미래신호 각각 "신호 있음/약함/없음/미검증")를 레이더/막대로. 0~100 단일 점수는 넣지 않는다.
4. **매물 주소 자리**: "행정동 + 최근접 역/아파트 + 반경 500m 동종 점포 수" 까지. `address_point=null`을 UI에서 "정확한 위치는 매물 확보 시 제공" 으로 표기.
5. **배치**: 분기 데이터 갱신 시 피처 번들 재빌드 → 원자적 스왑([postgres-migration-plan.md](postgres-migration-plan.md)). 입지 점수 사전계산 테이블은 없음(점수가 없으므로).
