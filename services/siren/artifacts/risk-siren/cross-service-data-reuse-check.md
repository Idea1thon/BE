# 점검: 가맹점 매출·손익 데이터를 입지 추천 서비스에 활용 가능한가

- 실행일: 2026-09-04
- 범위: 위험 사이렌의 `branch_reports`(월별 운영보고서 P&L) ↔ `data-analysis` 입지 추천 서비스
- 방법: `data-analysis` 설계 정본 읽기 전용 검토 (코드 미수정)
- 결론: **개념은 추천 서비스가 명시한 #1 갭과 정확히 일치. 그러나 현재 합성 데모 데이터셋은 활용 불가 (그중 하나는 추천팀의 핵심 설계 가드를 위반).**

## 1. 추천 서비스가 명시한 갭 (3개 문서가 같은 말)

| 문서 | 표현 |
| --- | --- |
| `.claude/context/metric-contract.md` §학습모델 재검토 조건 | "실제 신규 점포의 개·폐점일, 4개 분기 생존, **일관된 매출·손익**, 보증금·월세·면적, 브랜드·영업형태 … 확보하고 시간 순서 검증 가능할 때만 재검토. 2026-09-01: **매출·손익·보증금·월세·면적·브랜드는 미확보 → 학습모델 재검토 불가**" |
| `artifacts/10-analysis/feature-evidential-value.md` §1 | "결정적 한계: **신규 점포 매출·손익·브랜드 outcome 없음**. 이 검증은 'FC가 폐업/생존과 통계적으로 연관되는가'까지만. '좋은 입지 = 성공'은 검증 불가" |
| `docs/입지추천_기능요구사항_하네스대응.md` §4-3 | "**신규 점포 성공·매출·손익 outcome이 전혀 없다.** 검증에 쓴 outcome은 전부 인허가 폐업/생존 프록시" |

추천 서비스는 이 갭 때문에 **가중 합산 입지 점수를 만들지 않기로** 확정했다 (ADR-001, evidence-first). 27개 FC 중 폐업/생존에 단조 신호(|ρ|≥0.25)를 가진 것 0개, 전체를 합쳐도 설명력 +6%p.

## 2. 매핑: siren P&L 이 재검토 조건 체크리스트의 무엇을 채우나

| metric-contract 재검토 조건 항목 | siren `BranchMonthlyReport` (`service/siren/models.py`) |
| --- | --- |
| 일관된 **매출·손익** | ✅ 월별 P&L — 홀/배달/포장 채널별 매출, 매출차감, 매출원가, 인건비, 변동비, 운영비, 금융비용. 파생: `net_sales`, `operating_profit`, `operating_margin`, `labor_ratio`, `delivery_ratio`, `coupon_ratio` (`reports.py`) |
| **브랜드·영업형태** | ✅ `franchise_id`, `industry_code`(음식점 10종) |
| **월세** | 🟡 `opex.rent_mgmt` (관리비 합산이라 순수 월세 분리는 추가 필요) |
| 보증금 | ❌ |
| 면적 | ❌ |
| 신규 점포 **개·폐점일** | ❌ — 데모 점포는 t=0부터 "운영 중", 개점 이벤트 없음 |
| 개점 후 **4개 분기 생존** | ❌ — outcome 라벨(healthy/decline)은 관측이 아니라 **설계**로 배정 |
| 기존 업종 없던 지역(greenfield) | ❌ — 기존 상권에만 배치 |

siren 은 체크리스트의 **매출·손익 + 브랜드 + (부분) 월세**를 커버한다. 나머지(개·폐점일·생존·greenfield)는 이미 `data-analysis` 가 인허가 이식으로 확보한 부분이다. **개념적으로는 두 데이터가 합쳐지면 재검토 조건 대부분을 충족한다.**

## 3. 현재 합성 데모 데이터셋을 쓸 수 없는 이유

### 3-1. 순환 / 동어반복 — 추천팀 핵심 가드 위반 (결정적)

데모 순매출 = `업종 기준액 × 그 상권×업종의 실제 추정매출 추세 지수(감쇠) × 시나리오 드리프트 × 노이즈` (`service/siren/demo/generate.py`).

즉 **추정매출(FC-31)을 앵커로 넣어 생성**한 데이터다. 이걸로 "추정매출이 점포 실적을 예측하는가"를 검증하면 앵커로 심은 상관을 되찾을 뿐이다.

- ADR-001 / Phase 1 이 명시적으로 경계한 함정: "A안 F1 0.93 = 과거 매출 재현 동어반복"
- `metric-contract.md` §금지된 해석: **"매출이 높은 지역이므로 신규 점포도 성공한다"** — 합성 데이터로 이걸 "증명"하면 정확히 이 금지사항
- 결과: **거짓 양성**을 만들어 추천팀이 몇 주간 검증해 세운 결론을 무너뜨림

### 3-2. 표본 크기

`feature-evidential-value.md` 검증: n = 2,108 / 5,430 / 556. 데모: **n = 20** (20 점포 × 특정 20개 상권×업종 셀). 통계적 검증 불가.

### 3-3. 운영점 ≠ 신규점

`§4-3`, `metric-contract` 재검토 조건 모두 **신규** 점포 대상. 데모 점포는 "이미 운영 중"이라 개점일·1년 생존·greenfield outcome 이 없다. 시나리오는 관측이 아니라 라벨.

### 3-4. 선택 편향 (실 데이터에도 해당)

운영보고서를 제출하는 점주는 비무작위 표본. 망한 점포는 보고를 멈춤 → survivorship bias. 인허가 폐업일자 지연 완충과 별개로 보정 필요.

## 4. 지금 재사용 가능한 것

| 자산 | 활용 |
| --- | --- |
| **데이터 스키마** `BranchMonthlyReport` + `reports.py` 파생 지표 | 추천팀이 "store outcome panel"(`build_feature_outcome_panel.py` 의 실적 측) 을 설계할 때 쓸 완성된 명세. 운영보고서 폼 → 정규화된 손익 레코드 변환 규칙 포함 |
| **공간 조인 메커니즘** | siren 의 `location.x_5181/y_5181 → 반경(EPSG:5181) → 상권×업종 feature` 조인과 `trade_area_code → market_data` 조인이 동작 검증됨. 추천 outcome panel 이 필요로 하는 바로 그 조인 |
| **provenance 패턴** | `data_provenance.by_signal` 로 신호별 실측/합성 구분 — outcome panel 에서 "실 실적 vs 추정" 구분에 재사용 |

## 5. 진짜 활용 경로 (제품·데이터 전략)

siren 제품이 **실제 운영보고서를 규모 있게 수집**하면 (수백 점포 × 수십 개월, 알려진 좌표), 그게 추천 서비스의 결정적 갭을 메우는 데이터가 된다. 단:

1. 여전히 **"기존 점포 실적"** — "신규 점포가 여기서 성공하나"의 프록시. 그러나 인허가 폐업/생존보다 훨씬 나은 신호 (연속 손익, 채널 구성, 비용 구조)
2. 개·폐점일·greenfield 는 인허가 데이터(`음식점_인허가_서울.csv`)와 좌표·업종 조인으로 보완
3. **시간 순서 검증 필수**: t 시점 입지 feature → t+k 시점 점포 outcome. 동시점 상관은 §3-1 함정
4. survivorship bias 보정 (보고 중단 = 폐업 프록시로 별도 처리)
5. `metric-contract.md` 재검토 조건의 남은 항목(보증금·면적)도 운영보고서 폼에 추가하면 체크리스트 거의 완성

## 6. 데모에서의 취급

- 추천 카드에 **"이 입지 반경 500m 동종 가맹점 실적(합성)"** 참고 패널로 표시는 가능
- 단 `synthetic=true` 명시, `fit_tier`·정렬·`data_confidence` 에 **미반영** (D4 규칙 + §3-1 순환 리스크)
- 절대 점수 요소·검증 데이터로 쓰지 않음

## 7. 권고

1. 현재 합성 P&L 을 추천 서비스 스코어링·검증에 **연결하지 않는다** (§3-1 이 disqualifier)
2. `BranchMonthlyReport` 스키마와 공간 조인을 추천팀의 outcome panel 설계 **참조 스펙**으로 공유
3. 데이터 전략 문서화: "siren 이 실 운영보고서를 축적하면 → 추천 서비스 `학습모델 재검토 조건`의 매출·손익·브랜드 항목 충족 경로" (단 신규점 프록시·시간순서·선택편향 조건 명시)
4. 통합 PR 시 두 서비스는 **데이터는 분리, 스키마·조인 유틸은 공유** 구조 유지
