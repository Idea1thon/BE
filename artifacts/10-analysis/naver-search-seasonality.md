# 네이버 검색트렌드 계절성·이상치와 현재 관심도 분리 (2026-09-02)

FC-41(지역 검색 관심도)·FC-42(업종 검색 관심도)의 "여름 급등을 상시 상승 추세로 오독"(F12) 대응. `_요약.csv`의 `최근3개월_rel평균`·`최근6개월_기울기`가 raw `rel_index` 기반이라 생기는 문제를 실측으로 확인하고, **현재 관심도**와 **지속 추세**를 분리하는 사용 규칙을 고정한다.

- 스크립트: `scripts/analyze_naver_seasonality.py`
- 입력: `data/네이버트렌드/{업종,자치구,행정동}_검색트렌드_월.csv` (202101~202608, 68개월)
- 산출: `output/feature_validation/naver_seasonality.csv`(key별 지표)·`naver_seasonal_factors.csv`(key×월 계절지수)·`naver_seasonality_summary.json`, 그림 `output/figures/feature_validation/naver_seasonality.png`

## 방법 (scipy 없이)

1. **계절지수** SI[월] = (rel_index / 중심 12개월 이동평균)의 월별 **중앙값**, 평균=1 정규화. 중앙값이라 단일 이상치에 강함.
2. **탈계절 시계열** = rel_index / SI[월].
3. **이상치 탐지**: rel_index > 2.5× 직전 12개월 중앙값 **또는** raw_ratio ≥ 90 (네이버 데이터랩 상한 100 근처).
4. **surge 진행중**: 최근 3개월 내 이상치 또는 최신값 > 직전 12개월 중앙값 ×2 → 추세 판단 보류(`robust_slope=None`).
5. **YoY(clean)** = rel[m]/rel[m−12]의 최근 평균, 이상치 월 제외.

## 핵심 결론

### 1. 10개 외식업 검색 관심도는 **완만한 계절성**만 있다

| 지표 | 값 |
| --- | --- |
| 계절 진폭(peak/trough 배수) | **1.2 ~ 1.6x** (한식 1.57 최대, 호프 1.20 최소) |
| 공통 패턴 | **봄(3~4월) peak · 여름(7~8월) trough · 가을(9~10월) 회복** |
| 탈계절 12개월 추세 | 전 업종 **+1.4 ~ +4.3%/월** (완만한 우상향, YoY(clean) 1.1~1.3) |

→ 그림 왼쪽 패널. 모든 업종이 같은 모양이라 **Mar→Aug 구간 raw 기울기는 항상 '하락'으로 나온다** — 실제로 raw 6개월 기울기가 8/10 업종에서 음수(−3.7 ~ +1.9%/월)인데, 탈계절 기울기는 전부 양수. **이게 F12의 정체**: 계절 저점으로 내려가는 걸 추세 하락으로 오독.

### 2. 호프-간이주점 2026 여름 급등은 **계절성이 아니라 단발 서치 급등 + 상한 캡 아티팩트**

| 월 | rel_index | raw_ratio |
| --- | ---: | ---: |
| 202604 | 4.94 | 4.05 |
| 202605 | 13.98 | 12.16 |
| 202607 | **109.77** | **100** (데이터랩 상한) |
| 202608 | 33.91 | 30.99 |

- 2021~2025년 7월엔 이런 패턴이 **없다**(그림 오른쪽 패널). 계절 재현이 아님.
- `raw_ratio`가 질의 구간 최댓값이라 100으로 정규화됨 → `rel_index` = raw/anchor가 폭증.
- raw 6개월 기울기 **+44%/월** → "폭발적 성장"으로 읽히지만 `surge_active=true`로 **추세 판단 불가**.
- 이게 실제 트렌드(하이볼·생맥주 유행)인지 데이터 파이프라인 문제인지는 다음 분기(202609~) 데이터로 확인. 현재는 **미검증 급등**으로만 표기.

### 3. 이상치·surge 분포

- 이상치 보유 key 139 / 459 (최근 6개월 내 38). surge 진행중 30 (업종 1=호프, 자치구 2, 행정동 27).
- **행정동 grain은 노이즈가 크다**: rel_index 0.02~0.32 소신호라 작은 절대 변동도 배수로는 2.5x를 넘음. FC-41은 자치구 grain을 우선하고 행정동은 보조로만.
- 탐지기는 보수적이라 **빠른 성장 국면의 과거 월**(일식 2022말, 중식 2024초 등)도 이상치로 잡는다 → robust 추세 계산에서만 제외하고 해석엔 쓰지 않음.

## 현재 관심도와 지속 추세의 분리 (계약)

사용자의 “최근 한 달 이내 관심이 높은 음식·업종” 요구는 **현재 관심도**로 기록한다. 계절성은 실제 소비·검색 관심일 수 있으므로 제거해 숨기지 않는다.

- 현재 관심도 = 최신월 원계열 `rel_index` + 최근 3개월 원계열 평균. 후보 파이프라인에서는 이 값과 계절 국면(피크월·저점월)을 `context_notes`·RAG evidence에만 기록한다.
- 현재 관심도는 절대 검색량이 아니다. 네이버 데이터랩의 서울 앵커 대비 상대지수이며, 후보 지점·상권의 검색량이나 매출이 아니다.
- 현재 관심도 배수는 **`yoy_clean_recent_mean`(전년 동월 대비, 이상치 월 제외)**을 쓴다. '최근 3개월 ÷ 전체 5년 평균'은 장기 우상향 계열(커피 등)에서 항상 >1이 되어 오해를 준다(2026-09-02 교체). 상태 라벨(`≥1.2` 상승 / `≤0.85` 하락 / 유사)은 표시용 휴리스틱일 뿐 후보 등급·정렬·신뢰도에 영향 없음. `surge_active`면 라벨은 "미검증 급등"이 우선한다.
- `robust_slope12`(탈계절·이상치 제외)는 **계절성을 제거했을 때도 지속 상승인지 점검하는 분석용 지표**다. 현재 유행을 표현하거나 후보 등급·정렬 가점을 만드는 데 사용하지 않는다.
- `surge_active=true`이면 최신 관심이 높더라도 `미검증 급등`으로 표시하고, 지속 추세로 해석하지 않는다.
- 최신월이 업종의 계절 피크월이면 `계절성 피크월`로 표시한다. 이는 “현재 해당 계절에 관심이 높다”는 맥락이지 연중 수요나 입지 품질의 증거가 아니다.

## FC-41·42 사용 규칙 (계약)

프로파일 §5 FC-41·42 `activation.formula_when_active`에 반영:

1. 파이프라인의 현재 관심도는 **raw 최신월·최근 3개월 평균**으로 표시한다. 계절 보정값을 현재 관심도 점수로 사용하지 않는다.
2. `robust_slope12`는 지속성 진단용으로만 보존한다. raw `최근6개월_기울기`는 계절 아티팩트라 후보 해석에 사용하지 않는다.
3. **`surge_active=true`이면 "미검증 급등"만 표기**하고, 신규 진입 유불리·성장 가점으로 사용하지 않는다(호프 2026 케이스).
4. 계절 피크·저점은 현재 시기의 맥락으로 표시하되, 연중 수요나 성공 가능성으로 확대 해석하지 않는다.
5. FC-41은 **자치구 grain 우선**, 행정동은 소신호·노이즈라 보조 서술만.
6. FC-41·42는 검증상 "신호 없음"(§9-1) — 위 규칙을 지켜도 `context_notes` 중립 서술이며 판정·정렬 근거 아님.

```bash
.venv/bin/python3 scripts/analyze_naver_seasonality.py
```
