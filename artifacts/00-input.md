# 입력 및 범위

## 목표

중소 프랜차이즈 본사와 가맹 창업 희망자가 시도·시군구·행정동을 선택하고 업종 및 특별조건을 입력하면, 선택 범위 안의 입지 후보와 데이터 근거를 확인하는 웹서비스를 설계한다.

## 사용자 입력 계약

- 시도: 필수
- 시군구: 필수
- 행정동: 선택
- 업종: 필수
- 특별조건: 선택 텍스트

## 기대 출력

- 3~5개 후보 카드 또는 근거가 충분한 후보 수
- **후보 = 명명된 지점**(아파트 단지·역), 상권 폴리곤이 아님 (2026-09-02 재설계). 출력: 시>구>동>앵커명 "인근">좌표>참조 상권. 예: "송파구 잠실동 · 리센츠아파트 인근 (잠실새내역 210m, 잠실새내역 상권 배경)"
- 정밀도 `지점`(앵커 좌표 ±수십 m)이 기본. "@@아파트 @@동 @@호" 수준은 생성 금지(데이터 없음). `precision`으로 한계 표시
- 추천/조건부 검토/주의 상태
- 추천 근거와 반대 근거 — **지점 반경 값(역·버스·아파트)과 상권/행정동 배경값(유동·업종·인구)을 구분 표기**
- 누락 데이터와 기준 시점
- 검증된 매물 데이터가 있는 경우에만 상세주소·매물 링크

## 중요한 제약

- 기존 Top-K 학습 순위를 운영 추천 성공확률로 사용하지 않는다.
- 현재 저장소만으로 개별 공실 매물의 상세주소·월세·면적·주차·링크를 제공할 수 없다.
- 출력 위치는 "상권 코드"로 끝내지 않는다. 후보는 좌표를 가진 지점(아파트·역)이고, 시>구>동>앵커명>좌표로 낸다. 데이터가 없는 동·호수·출구번호·매물은 만들어내지 않고 `precision`으로 한계를 표시한다.
- 상권 폴리곤은 후보 단위가 아니라 "지점이 참조하는 업종·유동 배경값의 grain"이다. 상권은 서울 27%만 덮으므로 나머지는 행정동 배경값.
- RAG는 후보를 선정하지 않고 구조화 Evidence를 설명한다.
- 데이터나 산출물 삭제는 별도 승인 전 수행하지 않는다.

## 사람 승인 지점

- 임시 후보 지수와 임계값
- 외부 API 및 부동산 매물 연동
- 합성 SNS 데이터의 표현
- 공모전 제출과 서비스 배포

## 2026-09-02 뉴스 부분 재실행 입력 (GPT/Codex)

- 데이터 채널: 네이버 뉴스 API
- 검색어: `서울시 재개발` 단일 검색어만 사용
- 범위: 현재 시점에 수동 검색한 결과 snapshot
- 운영 제약: 자동화·예약·백그라운드 갱신 없음
- 이전에 2개 검색어로 수집했던 네이버 snapshot은 이번 단일 검색어 snapshot으로
  교체했다. 파이프라인은 `naver_news_snapshot.jsonl` 하나만 정적으로 읽는다.
