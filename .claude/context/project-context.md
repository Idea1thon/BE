# 프로젝트 컨텍스트

## 제품 목표

서울시 상권 데이터를 바탕으로 중소 프랜차이즈 본사와 가맹 창업 희망자에게 신규 점포 후보지를 설명 가능한 방식으로 제안한다.

현재 범위는 **정확한 개별 매물의 성공 확률 예측**이 아니라, 사용자가 고른 지역 안에서 검토할 가치가 있는 상권 후보를 찾고 근거와 위험을 함께 제시하는 것이다.

## 사용자 입력

입력은 자유 프롬프트가 아니라 웹 폼이 기준이다.

1. 시도: 필수
2. 시군구: 필수
3. 행정동: 선택
4. 업종: 필수 구조화 필드
5. 특별조건: 선택 텍스트. 백엔드에서 예산, 면적, 주차, 영업시간, 고객층, 배달/홀 중심 등의 구조화 필드로 변환한다.

서울 서비스에서는 일반적인 `시도/시군구/행정동` 계층을 `서울특별시/자치구/행정동`으로 표시한다.

## 추천 원칙

- 선택 지역 밖의 후보는 생성하지 않는다.
- 업종별 점포와 매출을 지역 공통 지표보다 우선한다.
- 상권, 상권배후지, 행정동 값을 독립 피처처럼 중복 합산하지 않는다.
- 결과는 `추천`, `조건부 검토`, `주의` 후보로 제시한다.
- 종합값이 필요해도 예측 확률로 부르지 않는다. 임시 지수는 버전과 산식을 공개한다.
- 각 후보에 추천 근거, 반대 근거, 누락 데이터, 기준 분기, 공간 단위, 출처를 함께 반환한다.
- 정확한 주소와 부동산 매물 링크는 별도 매물 데이터가 있을 때만 제공한다.

## 공간 단위

1. 상권 폴리곤: 기본 분석·후보 단위
2. 상권배후지 폴리곤: 주변 수요와 겹침을 설명하는 보조 단위
3. 행정동: 사용자 필터와 상권 미포함 지역의 fallback 단위
4. 개별 매물: 현재 저장소 데이터만으로는 지원하지 않음

공간 폴리곤은 겹칠 수 있다. 후보 점포 좌표가 생기면 point-in-polygon으로 해당 상권과 배후지를 연결하고, 겹침을 임의로 분할하지 않는다.

## 출력 위치 표현 (2026-09-01 추가)

입지 추천 결과는 상권 코드가 아니라 **사람이 알아볼 수 있는 위치**로 출력한다: `시 > 구 > 동 > 장소명(상권_코드_명) > 대표 좌표 > 폴리곤`, 그리고 겹침 크로스워크로 연결된 인접 단위. 상세 계약은 `artifacts/20-method/candidate-selection-spec.md` 1-1절, `rag-evidence-schema.json`의 `location`.

- 지금 가능한 최대 정밀도(`precision`)는 `상권` 수준(장소명 + 좌표 + 행정동).
- "@@아파트 / @@역 3번출구" 수준은 POI·아파트 단지 경계·매물 데이터가 필요하며 `nearby_anchors`·`address_point` 이식 슬롯으로 둔다. 데이터 없이 이 수준으로 표현하지 않는다.

## 이미 확인된 한계

- 기존 A형 Top-K 모델의 높은 F1은 과거 매출 지속성에 거의 전적으로 의존한다.
- 성장형 B 모델은 정확도가 낮고 업종별 가중치가 불안정하다.
- 기존 학습 데이터는 대상 업종 점포가 전혀 없던 상권을 제외해 진정한 신규 진입을 평가하지 못한다.
- 상주인구, 직장인구, 아파트는 계단식 갱신 데이터이므로 분기 추세로 쓰지 않는다.
- 상권변화지표는 업종 구분이 없으므로 지역 배경 리스크로만 쓴다.
- 임대료·공실률은 넓은 시장권역 통계여서 개별 매물 조건을 대체하지 못한다.
