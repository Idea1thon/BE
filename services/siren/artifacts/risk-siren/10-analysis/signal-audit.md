- 실행일: 2026-09-04
- 실행 주체: orchestrator (inline, 독립 QA는 RS-04에서 분리)

- 상태: current / 사람 승인 필요 (가중치·임계값·SR-05 경계)

## 1. 2층 위험 모델

```
risk result
├─ market_risk   (상권×업종, 서울시 공개데이터 실측, 항상 계산 가능)
│   ├─ SR-01 폐업률          ← data/인허가/음식점_상권분기_패널.csv + 음식점_인허가_서울.csv
│   ├─ SR-02(market) 매출감소 ← data/추정매출/*/*(추정매출-상권)*.csv
│   └─ SR-03 경쟁업체 등장    ← data/인허가/음식점_인허가_서울.csv (좌표+인허가일자)
├─ branch_risk   (가맹점 단위, 데모는 합성 / 운영은 점주 입력·본사 연동)
│   ├─ SR-02(branch) 매출감소 ← 월별 운영보고서 순매출
│   └─ SR-05 수익성 악화      ← 월별 운영보고서 손익 (신규)
└─ review_signal (보조, 종합 점수 밖)
    └─ SR-04 리뷰 반응        ← 합성 리뷰 (긍정/부정), 있을 때만 표시
```

종합 점수(`risk.score` 0~100, `risk.grade`)는 **SR-01·SR-02·SR-03·SR-05**만으로 계산하며 market·branch 두 층이 모두 계산됐을 때만 산출. 한 층이라도 비면 `calculation_status=partial` + 어느 층이 비었는지 명시. 시장 통계를 가맹점 고유 위험 점수로 합산해 "이 점포 폐업 임박"처럼 읽히게 하지 않는다.

**SR-04는 보조 신호**다. 별도 `review_signal` 블록에 0~100 서브점수·방향·경고 플래그를 담고, 종합 점수/등급을 바꾸지 않는다. 안내 문구와 관심 목록(watchlist) 플래그에만 반영한다. 리뷰가 없는 가맹점(다수 예상)은 `review_signal.status="missing"`이며 종합 점수는 영향받지 않는다. 나중에 사람 승인으로 소가중치 편입을 검토할 수 있다.

## 2. 신호별 감사표

### SR-01 폐업률 (market)

| 필드 | 내용 |
| --- | --- |
| definition | 특정 상권×업종에서 최근 기간 폐업한 음식점 수의 비율 (%) |
| 원천 | `data/인허가/음식점_상권분기_패널.csv` (298,448행, 1,630 상권 × 10 업종, 2021Q1~2026Q3) |
| 필드 | `기준_년분기_코드, 상권_코드, 업종코드, 영업중_수, 신규개업_수, 폐업_수, 개업률, 폐업률, 분기_상태` |
| **분모 (검증됨)** | 파일의 `폐업률` = 당분기 `폐업_수` ÷ **직전 분기** `영업중_수` × 100. 첫 분기는 당분기 `영업중_수`로 폴백. `개업률`도 동일 분모. (상권 3001491·CS100001, 3120189·CS100009 두 계열에서 손계산 일치 확인) |
| period | 분기. rolling 2·4분기(=6·12개월)는 `폐업_수` 합 ÷ 창 시작 직전 분기 `영업중_수`로 확장 가능 |
| grain | 상권_코드 × 업종코드 × 분기 |
| 0 처리 | 직전 분기 `영업중_수` = 0 이면 `not_calculable` (0으로 치환 금지) |
| `분기_상태` | `완전`(285,472) / `부분`(12,976, ~4.3%). `부분` 분기는 폐업/개업 집계 미완 → `partial`로 표시하고 rolling 창에서 제외하거나 uncertainty 강제 |
| 최신성 | 2026Q3까지 (부분). `완전` 최신은 대체로 2026Q2 |
| status | **usable** (상권×업종 단위). 프랜차이즈 브랜드 단위 아님 |
| risk / 다음 Agent 주의 | (1) CLAUDE.md의 공식 두 공식(전년말 계약 유지 분모, 가동 가맹점 분모)은 **가맹본부 공시 데이터가 필요**하며 이 데이터셋엔 없음. 데모는 브랜드 코호트 폐업률을 `synthetic_franchise_cohort`로 생성하고 명시. (2) 행정 폐업신고 기준 → 명의변경·휴업 노이즈, 무단폐업 누락. (3) `영업중_수`가 분기말/분기중 어느 시점인지 원천 정의 미확인 → Evidence에 "분기 영업중 수" 그대로 기록, 재해석 금지 |

인허가 raw(`음식점_인허가_서울.csv`, 684,820행, 좌표 645,539건, `인허가일자` 1900~2026-08, `폐업일자` ~2026-09)로 임의 기간 rolling 폐업/개업을 상권·좌표 단위로 직접 산출 가능. 업종코드 결측 105,819행(15.5%) 주의.

| 필드 | market 층 | branch 층 |
| --- | --- | --- |

| grain | 상권_코드 × 서비스_업종_코드 × 분기 | branch_id × 월 |

### SR-04 리뷰 반응 (보조 신호, 종합 점수 밖)

| 필드 | 내용 |
| --- | --- |
| definition | 최근 리뷰의 부정 반응 비율과 증가 추이. **보조 점수** — 종합 위험 점수·등급을 바꾸지 않고 안내 문구·watchlist 플래그에만 반영 |
| 원천 | 실데이터 없음(`data/` 전수 확인). 데모는 **합성 리뷰 생성** (사용자 결정 2026-09-04, 선택지 a). `source: "synthetic_reviews"` |
| 생성 사양 | 가맹점별 리뷰 레코드 `{review_id, branch_id, written_at, rating(1~5), text, sentiment_label(긍정/부정/중립), sentiment_source}`. 긍정 성격·부정 성격 한국어 음식점 리뷰 템플릿. 시나리오 연동(악화 가맹점일수록 부정 비율·건수 증가). **일부 가맹점은 리뷰 0건** → `review_signal.status="missing"` |
| 집계 | 결정론: `review_count`, `negative_count`, `negative_ratio` = negative/total, `negative_ratio_previous_period`. 서브점수는 `negative_ratio` 및 직전 대비 증가분으로 산출 (0~100), 기존 `calculate_reviews` 로직 재사용 |
| LLM 경로 | `llm_mode`가 분류 보조를 켜면 리뷰 `text`를 재분류하고 생성 시 라벨과 일치율을 로깅. 점수는 결정론 집계값 사용 (LLM이 수치 승격 금지) |
| period | 최근 리뷰 기간 + 직전 기간 대비 |
| grain | branch_id × 리뷰 |
| status | 데모: 리뷰 있으면 usable(합성), 없으면 **missing** (다수 예상, 정상) |
| risk / 주의 | (1) 종합 점수에 **가중치 0** — `review_signal` 블록 분리. (2) 모든 리뷰·집계에 합성 표시(`data_provenance`). (3) 리뷰 없음이 위험 완화 신호로 해석되지 않도록 — 없으면 그냥 표시 안 함. (4) 부정 리뷰 텍스트가 특정 실존 인물·업체를 지칭하지 않도록 템플릿 관리 |

### SR-05 수익성 악화 (branch, 신규)

| 필드 | 내용 |
| --- | --- |
| definition | 월별 운영보고서 손익에서 영업이익·마진·비용구조 악화 추세 |
| 원천 | 월별 운영보고서 (데모=합성 생성기, `source: "synthetic_self_reported"`) |
| 입력 항목 | 매출원가(식자재·부자재·주류·음료·기초/기말 재고), 인건비(정규직·파트타임·4대보험·식대복리후생·단기인력), 변동비(플랫폼수수료·배달대행료·소모품·수도광열·마케팅), 운영비(임차료관리비·기기렌탈·통신IT·세무기장·보험료·카드수수료), 금융(대출이자·기타잡비) |
| 파생 지표 | `net_sales`(홀+배달+포장 − 환불 − 쿠폰), `cogs`(식자재+부자재+주류+음료+기초재고−기말재고), `gross_profit`, `labor_total`, `opex_total`, `operating_profit` = gross_profit − labor_total − 변동비 − opex_total − 금융, `operating_margin`, `labor_ratio`=labor_total/net_sales, `delivery_ratio`=배달/gross_sales, `coupon_ratio`=쿠폰/gross_sales |
| period | 최근 3개월 vs 직전 3개월, 최신 구간 가중 (SR-02와 동일 창) |
| 악화 트리거 후보 | 영업이익 3개월 연속 음수 / 영업이익률 하락폭 / labor_ratio 상승 / coupon_ratio 상승 / 대출이자 증가 (가중치·임계값 provisional, **사람 승인 필요**) |
| grain | branch_id × 월 |
| 분모 0 | `net_sales` = 0 인 월 → 비율 지표 `not_calculable`, 매출 0 자체는 강한 위험 신호로 별도 처리 |
| status | 데모 usable(합성) / 운영은 점주 입력 없으면 `missing` |
| risk / 주의 | (1) CLAUDE.md의 4신호 경계를 확장하는 항목 → 가중치·임계값·트리거 문구 전부 `사람 승인 필요`. (2) 재고 기말>기초 시 원가 음수 방지 로직 필요. (3) 점주 자가입력이므로 신뢰도 가중 낮게, Evidence에 unverified 플래그 |

## 3. 데모 데이터셋 사양 (RS-03 구현 입력)

| 항목 | 값 |
| --- | --- |
| 가맹점 수 | 20 |
| 이력 | 24개월, 2024-04 ~ 2026-03 (매출 앵커가 존재하는 구간) |
| 레코드 | 20 × 24 = 480 월별 운영보고서 |
| 업종 | 10개 음식점 업종(CS100001~CS100010)에서 분포 배정 |
| 상권 | 서울시 발달/골목 상권 중 인허가 패널 `완전` + 추정매출이 2024Q2~2026Q1 연속 존재하는 (상권_코드) 20개 선정 (구현 시 확정, 강남역 3120189·역삼역 3120197 등 후보) |
| 앵커 방식 | 각 월의 순매출 = 해당 (상권×업종) 분기 추정매출 지수의 월 배분값 × 가맹점 규모계수 × 시나리오 드리프트 × 재현가능 노이즈(seed=branch_id) |
| 시나리오 | healthy / slow_margin_squeeze / sales_decline / delivery_trap / debt_spiral / sparse |
| 생성 표시 | 모든 합성 필드 `source`에 `synthetic_*`, 응답에 `data_provenance.contains_synthetic=true` + disclosure 문구 |
| 저장 | `artifacts/risk-siren/demo/branch_reports/*.json`, 시장 집계 lookup은 `artifacts/risk-siren/demo/market_baseline.json` |

## 4. 계약(RS-02)에서 확정해야 할 항목

1. 요청에 `industry_code`, `trade_area_code`(또는 자치구+행정동), 가맹점 좌표 추가
2. 응답 `components`를 `market_risk` / `branch_risk` 2층으로 분리, `data_provenance` 블록 추가
3. SR-02 "최근 3개월" → market은 "최근 분기" 재정의, 필드명 분리 (`market_recent_quarter_change_pct` vs `branch_recent_3m_change_pct`)
4. SR-03 반경 N, 유사업종 매핑 규칙, "신규" 기준
5. SR-04: 합성 리뷰 채택(결정됨). `review_signal` 블록 스키마, 종합 점수 가중치 0, 리뷰 레코드 요청 필드 정의
6. SR-05 파생 지표 필드 목록과 악화 트리거, 전부 `provisional` + `사람 승인 필요` 표기
7. 종합 점수: SR-01·02·03·05 / 2층 모두 계산 시에만 산출하는 정책 확정 (pipeline-design 3절 기본안 유지). SR-04 제외
8. rolling 6·12개월(=2·4분기) 폐업률을 별도 필드로 유지
