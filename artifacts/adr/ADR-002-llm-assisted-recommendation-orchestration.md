# ADR-002: LLM 입력 해석·분석 계획 + 결정론적 추천 엔진

- 날짜: 2026-09-03
- 상태: 채택 (구현 전 설계)

## 맥락

와이어프레임은 지역을 선택형 UI로 지정하고, 업종·예산·면적·고객층·운영시간 등의 요구를 자유 텍스트로 입력하는 흐름이다. 정적 조건 파서만 사용하면 표현의 다양성과 조건 조합을 충분히 다루기 어렵다.

그러나 LLM은 관측 데이터의 상관관계를 자동으로 인과관계로 만들 수 없고, 현재 데이터에는 신규 점포의 매출·손익·생존 outcome과 개별 매물 데이터가 부족하다. LLM에게 후보 선정과 숫자 결합을 직접 맡기면 grain 혼합, 미래 데이터 누수, 결측 은폐, 근거 없는 인과 표현이 발생할 수 있다.

## 결정

LLM을 사용자 입력 직후의 분석 계획자(planner)로 배치한다.

```text
선택 지역 + 자유 텍스트
  → LLM 입력 해석·분석 계획
  → 결정론적 계약 검증·확인 질문
  → 읽기 전용 데이터 분석 도구
  → 후보·통계·Evidence JSON
  → 인과 주장/품질 게이트
  → LLM 설명 카드
```

### LLM이 담당하는 일

- 자유 텍스트에서 업종 후보와 조건을 추출한다.
- 조건이 모호하거나 충돌하는 경우 확인 질문을 만든다.
- 요청 목적에 따라 조회할 지표·기간·비교 대상을 분석 계획으로 제안한다.
- 읽기 전용 SQL/Python 분석 도구를 호출한다.
- 검증된 결과를 사용자가 이해할 수 있는 추천 설명으로 변환한다.

### 코드가 최종 권한을 가지는 일

- 선택된 지역의 코드·경계와 업종 코드 검증
- 조건의 단위 변환, 지원 여부, 충돌 판정
- 후보 생성, 하드 조건, 등급, 정렬
- 기간·업종·공간 grain·출처 검증
- 숫자·인과 주장·금지 표현 검증

LLM은 선택형 지역값을 변경하지 않으며, LLM이 제안한 조건은 `ResolvedInput`으로 확정되기 전까지 사실이 아니다. `unsupported_conditions`와 `confirmation_required`는 검증기가 결정한다.

## 인과관계 주장 정책

모든 분석 주장은 `descriptive`, `associational`, `causal` 중 하나로 표시한다.

- `descriptive`: 관측된 값과 집단 차이만 설명
- `associational`: 통제 변수를 포함한 연관성으로 설명
- `causal`: 사전 정의된 식별 설계와 반사실 검증을 통과한 경우에만 허용

LLM이 발견한 패턴은 기본적으로 가설 또는 연관성으로만 기록한다. 인과 주장을 허용하려면 별도의 준실험 설계, 처리 시점, 비교군, 사전 추세 및 위약 검증이 있어야 하며, 현재 추천 서비스의 자동 등급에는 사용하지 않는다.

## 안전장치

- 원천 CSV 전체가 아니라 버전·출처가 붙은 구조화 Evidence만 LLM에 전달한다.
- 도구는 기본적으로 read-only로 제한한다.
- 후보·등급은 LLM 장애와 무관하게 생성하거나, 입력 해석 실패 시 확인 요청으로 중단한다.
- 설명 카드의 수치와 주장은 Evidence 역추적 검사를 통과해야 한다.
- 검증 실패·LLM 장애·예산 초과 시 템플릿 설명 또는 `degraded=true`로 폴백한다.
- `data_version`, 모델 버전, 프롬프트 버전, 분석 계획을 로그에 남긴다.

## 결과

정적 코드의 고정된 조건 조합 한계는 완화하면서도, LLM이 데이터 결함이나 관측 상관관계를 인과관계로 포장하는 것을 방지한다. 이 결정은 [ADR-001](ADR-001-evidence-first-ranking.md)의 증거 중심 추천 원칙을 유지하고, 기존 C5 후보 엔진과 C6 Evidence 계약을 보존한다.

## 재검토 조건

- 신규 점포의 4분기 생존·매출·손익 outcome 축적
- 처리 시점과 비교군이 있는 자연실험 또는 준실험 데이터 확보
- LLM 분석 계획의 회귀 테스트와 비용·지연 목표 충족
